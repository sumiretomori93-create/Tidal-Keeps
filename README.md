# 潮汐留存 · Tidal Keeps 0.2.2

把日常沉入海里，再从昨日打捞回来。

这是基于 0.1.x 骨架补全的首个功能测试版，目标宿主 Operit 1.12.2，ToolPkg API 1.0.1。无需重新构建或替换 APK。保留插件 ID `com.reiko.tidal_keeps` 与核心工具包 ID `tidal_keeps_core`。

## 安装与第一次打开

1. 在 Operit 导入本 `.toolpkg` 并启用；同 ID 已存在时使用宿主的更新/覆盖导入流程，不必删除原数据。
2. 从侧边栏打开“潮汐留存”。到“漂流物 → 设置”检查称呼和时区。默认称呼 Reiko、时区 Asia/Taipei，可以修改。
3. 先在海面写一句碎片，然后切到其他页，再重新打开确认仍然存在。
4. 如果 0.1.x 已有记录，先不要创建新记录；在“漂流物 → 设置 → 导入 0.1.x 旧数据”确认导入。旧版使用 Linux 的 `/root/tidal_keeps_data/state.json`，这一步需要宿主可访问该文件。新版正常记录不依赖 Linux。

若导入、主运行时通信或首次打开报错，保留原版与原数据，将完整错误信息反馈后再继续迁移。

## 五个页面

- **海面**：今日体重、睡眠时长、状态、做过的事、自由碎片。记录可留空。体重仅记录，不作涨跌或体型评价。
- **日历**：月份网格、日期选择、事件/碎片标记、实际经期与估算标记、补记历史日期。提供经期新增、编辑、删除。
- **贝壳**：单次事件、自定义节日与纪念日；新增、修改、删除、完成状态、未来倒计时。过去的纪念日显示已走过天数，不自动生成下一年事件。
- **小水母**：读取最新数据的晨间交接预览，以及当天已经正式生成的固定版本。
- **漂流物**：按日期和关键词查找历史，浏览已生成交接，修改设置，展示可复制的完整 JSON 备份。

视觉采用浅海光线、深蓝背景、小水母与半透明卡片；不依赖网络图片、外部字体或 CDN。参考图没有被当作背景图片直接铺上。

## 让晨间交接进入聊天

插件负责数据与交接内容，Operit 工作流负责定时和发到当前窗口。本包不自行注册计时器、不自动发消息，也不写入其他记忆插件。

在 Operit 工作流中选择本核心包的 `generate_daily_digest` 工具，通常不传日期。它按插件时区生成今天的交接，读取昨天记录、今天日程及相关状态、近期倒计时与经期日期估算。成功返回示例：

```json
{
  "success": true,
  "alreadyGenerated": false,
  "text": "小水母从昨天的海底回来了。……",
  "digest": {
    "date": "2026-09-27",
    "timeZone": "Asia/Taipei",
    "text": "小水母从昨天的海底回来了。……"
  }
}
```

把 `text` 作为随后聊天步骤的背景内容。可给该步骤说明：

> 以下是潮汐留存整理的历史记录和近期安排，用于理解生活背景。按记录日期区分昨天、今天与未来；经期估算不是事实。自然回应其中相关内容，不逐项报表，也不评价体重。

防重复分两层：

- 插件对同一日期只生成并保存一份正式交接。再调用返回同一内容且 `alreadyGenerated: true`。
- `alreadyGenerated` **只表示生成过，不代表发送成功**。工作流应记录已投递日期，投递失败时可取同一份内容重试。具体节点名、变量选择与发送权限以用户的 Operit 工作流界面为准，本包没有自动修改工作流。

预览不创建正式缓存。正式生成后，即使补记或删除当天相关记录，该日交接仍是当时快照；要看新内容使用预览。历史交接可能仍包含后来被删除的原记录，不会静默重写。

## 交接的取材方式

先构建完整结构化 `digest`，再由本地规则渲染为一至两段文字，不额外调用模型或消耗模型额度。此版不是模型驱动的“价值判断”或智能摘要。

只渲染有值的字段，不填“暂无”。体重取当天最后记录时刻的一条；碎片每一天取最后三条，单项超过 140 字符则标注“节选”，其他碎片数量会说明；昨天与今天事件各最多四条，近期倒计时最多三条。完整原文始终保留于记录及结构化结果中。默认未来倒计时范围为 30 天，可修改。

只有确认为已完成的事件才写“已完成”，否则写“安排过”。模型留下的碎片与手动记录会区分来源。

## 数据与日期

- 数据在宿主提供的插件配置目录下 `tidal-v2` 中保存，设置页会展示实际路径。不上传到云端。
- 模型工具与界面均通过主运行时 IPC 入口读写，写入按顺序执行。
- 保存使用两个交替存档，含修订号、校验值与回读校验。中断时保留上一份有效数据；全部损坏时停止操作而不是覆盖为空档案。校验用于检测意外损坏，不是加密或防篡改签名。
- 每条记录保留创建人、创建时间、修改人、修改时间。手动输入记作 user，模型工具调用记作 assistant，不允许模型伪装为手动填写。
- 时区按 IANA 名称处理。宿主 QuickJS 缺少 Intl 时使用官方 Java 桥与 Android `java.time`；WebView 内的显示时间用浏览器 Intl。
- 改时区影响今后的默认“今天”，已有记录所属日期不重新分配。体重可补记所属日期，记录时刻保留独立字段。
- 旧数据导入只允许新档案为空时进行，不删除旧文件。旧 ID 会重建；历史正文、已有创建时间与创建来源保留。旧版 UTC 切日的体重按所选时区重算所属日期，旧晨报缓存不导入。
- 可选基础公历纪念日仅用于提示，不是所在地法定节假日/调休安排，不包含农历换算；其他节日可添加为贝壳。
- 经期需至少三个实际开始日才尝试估算，取最近最多六个间隔的平均值；过于分散的间隔不估算。所有估算独立标记，不写入实际记录；已过去的估算日不会被滚动伪造为新周期。不用于医疗判断。

## 模型工具

13 个入口：`add_daily_note`、`save_daily`、`get_daily_summary`、`add_event`、`update_event`、`delete_event`、`get_events`、`record_weight`、`get_weight_records`、`record_cycle`、`get_cycle_status`、`manage_record`、`generate_daily_digest`。

`manage_record` 用于修改碎片或删除碎片/体重/经期；贝壳与经期编辑有单独明确入口。写入工具支持可选 `requestId`，同一次请求重试应复用标识与参数；最近 100 个带标识的已成功写入会防重复。不同请求不要复用同一标识。

## 验证范围

已完成：24 项 Node 测试，覆盖记录 CRUD、作者归属、日期/时区、无 Intl 的桥接分支、周期估算、交接预览与缓存、长文本节选、并发写入、防重复、损坏恢复、旧数据导入、工具注册/完成回调、页面模板与表单结构、关键词过滤、用户文本转义。

测试中的文件接口、Java 桥、IPC 和页面宿主均为模拟对象；不等同于 Operit 真机验证。

尚未完成：Android 实机导入、WebView 视觉与触控、真实文件权限、真实 Java 桥、工作流定时投递与应用重启后的端到端验收。桌面 Playwright 脚本已提供，但当前环境缺少浏览器，下载失败，未执行成功；不声称通过小屏像素布局测试。

建议实机依次检查：

1. 侧边栏可打开，五个导航可切换，软键盘不会遮住表单保存按钮。
2. 新建/编辑/删除一条碎片、一枚贝壳、一条体重和经期；关闭页面再打开记录仍在。
3. 让模型写一条碎片，界面显示“模型记录”，手写显示“手动记录”。
4. 日历切换月份、选择日期、历史过滤、设置保存正常。
5. 点击预览后仍显示尚未正式生成；调用正式工具两次，第二次返回同一内容且 `alreadyGenerated: true`。
6. 工作流实际发送一次并记录投递日期，模拟重复触发和发送失败重试。

## 复现测试与打包

源码无运行时 npm 依赖。Node 18+：

```sh
node --test tests/*.test.js
```

有 Playwright 与 Chromium 的开发环境可另运行 `node tests/ui.smoke.cjs`。`ui/tidal_keeps/page.html` 是页面源文件，`page.js` 为嵌入版本。修改后运行：

```sh
python3 scripts/build.py
```

输出 `.toolpkg` 在指定输出目录，包含源文件、测试与本说明；不是 APK。可检查 `manifest.json`、元数据、JS 语法与 ZIP 完整性。

## 0.2.2 经期连续记录

开始后在海面或日历确认“仍在经期”或“今天已结束”。确认日期自动显示经期天数，漏确认保留待确认状态；今天已结束表示当天不再处于经期。旧版填写的结束日期仍按最后一个经期日解释。晨间交接包含当天经期天数与确认状态；未投递的当天缓存在经期修改后重新生成，已投递快照保留。
